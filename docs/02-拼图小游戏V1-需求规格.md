# 世界名画拼图小游戏 V1：需求规格

> 文档状态：已审核通过
> 版本：V1.3
> 上游基线：[任务背景与现状分析 V1.2](./01-拼图小游戏V1-任务背景与现状分析.md)
> 目标平台：桌面与移动浏览器上的响应式 React + TypeScript 前端应用
> 审核人：项目负责人
> 最后更新：2026-08-30

## 1. 文档目的

本文定义世界名画拼图小游戏 V1 必须提供的用户体验、关卡规则、边界和验收口径。它约束后续设计与开发，但不决定具体组件名称、状态管理库、切图算法、目录结构或构建工具。

## 2. 用户目标与成功标准

### 2.1 核心用户路径

1. 用户开始一轮新游戏。
2. 系统从本轮尚未使用的名画中随机选出一张，按当前关卡规则生成并打乱拼图。
3. 系统先展示完整原图 5 秒，随后显示可操作的打乱拼图。
4. 用户在左侧拼图窗口中先后点击两块切片，交换它们的位置。
5. 用户首次点击切片时，右侧计时器开始实时显示本关耗时。
6. 所有切片回到正确位置后，系统判定通关并显示耗时。
7. 用户选择“下一关”继续，或选择“退出游戏”结束本轮；退出后不保留进度。

### 2.2 用户可感知的成功标准

- 用户能清楚看到当前拼图、已选切片、实时计时与关卡结果。
- 每一关开始时拼图一定尚未完成，且用户始终可仅通过交换两块切片完成该关。
- 同一轮内不会重复出现同一张名画。
- 关卡之间与通关反馈具有平滑、非突兀的视觉过渡，不影响点击交换操作。

## 3. 背景与约束摘要

- 当前项目尚无应用代码；`assets/paintings/` 已入库 101 张 JPEG 名画与 101 条 `manifest.csv` 记录。
- 一轮固定为 100 关且同一图片不重复；图库可超过 100 张，现有 101 张及后续新增图片均可参与第 3–100 关的随机选择。
- V1 使用 React + TypeScript，面向桌面与移动浏览器。
- V1 不包含登录、进度保存、排行榜、多人游戏、音效或原生应用封装。

## 4. 已确认的业务与架构边界

- 游戏为单人、前端会话内体验；退出游戏或刷新页面后，不要求保留进度。
- 项目内随应用交付的名画图库及其元数据清单，是本轮图片选择和作品信息展示的真源。
- 图库只可收录来源机构明确标注为 CC0 或公共领域的图片；每张图片必须保留可核验的来源和许可记录。
- 每关拼图开始前先展示完整原图 5 秒；展示期结束前不允许切片交换。
- 每关的行列取决于游戏关卡难度与当前图片方向；横版与正方形图片优先增加列，竖版图片优先增加行。
- 用户操作的唯一必需方式是依次单击两个切片以交换位置。
- 时间从用户首次点击切片开始计入，直至本关完成。

## 5. 范围

### 5.1 本期范围

- 固定第 1 关《蒙娜丽莎》、第 2 关《星月夜》的 2×2 练习流程，以及第 3–100 关的随机、不重复流程。
- 接入并验收已随项目交付的 101 张名画图片及其元数据清单；完整一轮固定 100 关，不要求用完图库。
- 2 个固定 2×2 练习关及 20 个正式难度等级的递进规则。
- 将单张图片分割、打乱、两次点击交换、完成判定与每关计时。
- 每关开始前展示完整原图 5 秒的提示流程。
- 左侧拼图窗口、右侧实时计时信息区、通关结果与“下一关 / 退出游戏”操作。
- 平滑的基础视觉反馈与过渡动画。
- 针对核心业务规则的自动化验证，以及桌面和移动浏览器中的响应式人工交互验证。

### 5.2 非本期范围

- 用户注册、登录、云端账号、跨设备进度同步或本地持久化进度。
- 排行榜、分数、成就、社交分享、多人模式、音效、背景音乐或内购。
- 原生应用封装、离线安装包或针对特定机型的原生能力适配。
- 运行时在线下载、运营管理、自动更新或自动抓取名画图片库。
- 为真实图片授权、购买、上传或外部图片服务执行任何操作。

### 5.3 未来设计输入边界

- 拖拽交换、提示、撤销、暂停、难度选择、主题皮肤和排行榜可作为后续能力讨论，不属于本期交付。

## 6. 术语与业务口径

| 术语 | 定义 |
| --- | --- |
| 一轮游戏 | 从用户开始新游戏至选择退出或第 100 关完成的连续会话。 |
| 练习关 | 本轮第 1、2 关；分别固定使用《蒙娜丽莎》和《星月夜》，均切为 2 行 × 2 列。 |
| 正式 Level | 从第 3 关开始的难度组；除最后一组外，每个 Level 包含 5 关。 |
| 当前关卡 | 本轮正在进行或刚完成的单张名画拼图。 |
| 横版图片 | 宽度大于或等于高度的图片；正方形按横版处理。 |
| 竖版图片 | 高度大于宽度的图片。 |
| 正确位置 | 某切片在未切割原图中的原始行列位置。 |
| 已完成 | 所有切片均在其正确位置。 |
| 已用图片 | 当前一轮中已被选作任一关卡的图片；不得再次选取。 |
| 图片资产 | 本地随应用交付的一张名画图片，以及与其唯一对应的、可追溯元数据记录。 |
| 作品基本信息 | 作品名、作者/创作者、创作年代或年份、馆藏机构，以及来源与许可信息。 |
| 通关耗时 | 从本关首次点击切片到本关达到已完成状态之间的实际经过时间。 |
| 原图提示期 | 每关在拼图可操作前展示完整原图的固定 5 秒时间段；不计入通关耗时。 |

### 6.1 正式 Level 与切割规则

令 `L` 为从 1 开始的正式 Level 编号。第 `L` 个正式 Level 覆盖的游戏关卡为 `3 + 5 × (L - 1)` 至 `7 + 5 × (L - 1)`；最后一个 Level 可少于 5 关。

| 正式 Level | 横版 / 正方形 | 竖版 | 拼块数 |
| --- | --- | --- | --- |
| Level 1 | 2 行 × 3 列 | 3 行 × 2 列 | 6 |
| Level 2 | 3 行 × 3 列 | 3 行 × 3 列 | 9 |
| Level 3 | 3 行 × 4 列 | 4 行 × 3 列 | 12 |
| Level 4 | 4 行 × 4 列 | 4 行 × 4 列 | 16 |
| 后续 Level | 每升一级增加一条内部切割线，并按图片方向优先增加列或行 | 同左 | 由行数 × 列数决定 |
| Level 20 | 12 行 × 12 列 | 12 行 × 12 列 | 144 |

## 7. 功能需求

### FR-001：开始新一轮游戏

**目标**：让用户从零开始进入可玩的第一关。

**规则**：

- 系统必须在用户开始新游戏后创建新的本轮图片使用记录。
- 系统必须进入第 1 个练习关，并使用 2 行 × 2 列切割。
- 第 1 关必须使用由 `file` 字段文件名派生 ID 为 `mona-lisa__leonardo-da-vinci` 的《蒙娜丽莎》；第 2 关必须使用 ID 为 `the-starry-night__vincent-van-gogh` 的《星月夜》。
- 新一轮不得继承此前退出、刷新或完成的游戏进度与已用图片记录。

**验收标准**：开始新游戏后显示一个未完成的 2×2 拼图；本关计时尚未开始。

### FR-002：随机且不重复地选择名画

**目标**：保证一轮游戏中的名画具有随机性且不重复。

**规则**：

- 创建第 3–100 关时，系统必须只从本轮尚未使用、且未被练习关固定使用的图片中随机选择一张。
- 系统必须在该图片被选中后立即将其标记为本轮已用。
- 同一轮的 100 个关卡中，同一图片不得出现两次。

**边界与异常**：正式验收前，图库中至少应有 100 条合格资产，且两张固定练习图均可用。第 3–100 关从除已用图片外的整个图库随机选择；图片无法加载时遵循 FR-009。

**验收标准**：使用 100 个可识别测试图片完成一轮时，记录的图片标识无重复，且数量为 100。

### FR-003：按关卡和图片方向切割

**目标**：形成随进度提升、且适合图片比例的拼图。

**规则**：

- 第 1、2 关必须固定切为 2 行 × 2 列。
- 第 3 关起，系统必须按 §6.1 中的正式 Level 规则计算行数与列数。
- 对横版或正方形图片，系统必须优先通过增加列来提高难度；对竖版图片，系统必须优先通过增加行来提高难度。
- 每个正式 Level 除最后一个外必须包含 5 关；最后一个 Level 使用剩余关卡数。

**验收标准**：第 3–7 关中，横版/正方形图片均为 2×3，竖版图片均为 3×2；第 8–12 关均为 3×3；第 98–100 关均为 Level 20 的 12×12。

### FR-004：生成可完成的初始拼图

**目标**：避免用户打开时已通关，并确保每关都可通过本游戏的交换操作完成。

**规则**：

- 系统必须将切片置于一个不同于正确布局的初始排列。
- 初始排列必须由正确布局经有限次两两交换产生，或采用与此等价的可恢复排列。
- 系统不得把已完成布局作为可开始操作的初始布局。

**验收标准**：对每种切割规格重复生成初始布局时，均不等于正确布局；依次交换错位切片可以恢复正确布局。

### FR-005：展示原图提示

**目标**：让用户在开始拼图前有固定、平等的观察原图机会。

**规则**：

- 每关创建后，系统必须先展示该关的完整原图，持续 5 秒。
- 原图提示期内，拼图切片不得响应选中或交换操作，计时器不得开始。
- 5 秒结束后，系统必须展示该关的打乱拼图，并允许用户开始操作。
- 原图提示期的 5 秒不得计入通关耗时。

**验收标准**：每关开始均可看到完整原图持续 5 秒；提示期内点击切片不改变状态且计时保持零；提示结束后首次点击才开始计时。

### FR-006：两次点击交换切片

**目标**：让用户通过明确、低门槛的操作完成拼图。

**规则**：

- 用户首次点击任一切片后，系统必须将该切片作为待交换对象，并提供可见的选中反馈。
- 用户随后点击另一块切片后，系统必须交换两块切片的位置，并清除或更新选中状态。
- 当用户再次点击当前已选中的同一切片时，系统必须取消本次选择，不得交换切片；此前第一次点击视为失效。
- 交换完成后，系统必须重新判断拼图是否已完成。
- 切片交换和选中反馈应使用不妨碍连续操作的平滑视觉过渡。

**验收标准**：连续选择两块不同切片时，只有它们的位置互换；再次点击已选切片时，选中状态取消且所有切片位置不变。

### FR-007：从首次点击开始实时计时

**目标**：准确反映用户实际开始操作后的通关耗时。

**规则**：

- 本关加载完成时，计时器必须显示零且不得运行。
- 用户第一次点击切片的瞬间，系统必须开始本关计时。
- 计时器必须在右侧信息区实时显示经过时间，显示格式为不足一分钟时 `XX秒`，满一分钟时 `XX分XX秒`。
- 计时区域必须同时持续显示当前关卡序号，格式为“第 `X` / 100 关”；并显示练习关或正式 Level 标识。
- 拼图达到已完成状态时，系统必须停止计时，并保留该关最终耗时。

**验收标准**：未点击前计时为零；首次点击后读数递增；通关后读数停止变化并与结果显示一致；从第 1 关进入第 2 关及任一后续关时，计时区域显示正确的“第 X / 100 关”和难度标识。

### FR-008：通关结果与关卡流转

**目标**：让用户了解结果并决定继续或结束。

**规则**：

- 当所有切片处于正确位置时，系统必须判定本关通关。
- 系统必须显示本关通关耗时，以及“下一关”和“退出游戏”两个明确操作。
- 用户选择“下一关”后，系统必须从未使用图片中生成下一关，并重置该关的计时与选中状态。
- 用户选择“退出游戏”后，系统必须结束当前一轮；之后重新开始时不恢复本轮进度。
- 当第 100 关完成时，系统必须显示一段基础通关动画，以明确庆祝本轮完成；动画结束后必须只提供“退出游戏”操作。

**验收标准**：通关后显示本关最终耗时和两个操作；选择下一关不会重复本轮已用图片；选择退出后重新开始进入新的第 1 关。

### FR-009：图片加载失败处理

**目标**：在资源异常时避免无限等待或静默更换关卡图片。

**规则**：

- 加载当前关卡图片失败时，系统必须对同一图片重新加载，最多尝试 5 次。
- 同一图片连续 5 次加载失败后，系统必须停止进入该关，并向用户显示明确的“游戏故障”提示。
- 系统不得在连续失败后静默改用另一张图片。
- “游戏故障”提示必须提供“退出游戏”操作，用户选择后结束当前一轮且不保留进度。

**验收标准**：模拟前 4 次加载失败、第 5 次成功时关卡可继续；模拟连续 5 次失败时不显示可操作拼图且显示游戏故障提示。

### FR-010：固定的游戏界面布局

**目标**：让用户同时专注拼图与掌握时间。

**规则**：

- 游戏主界面必须将拼图窗口放在左侧。
- 游戏主界面必须将实时计时信息区放在右侧。
- 右侧信息区必须在本关进行时持续显示当前耗时。
- 在窄视口下，界面必须自适应为先拼图、后信息面板的单列布局；计时器在不滚动或仅最小滚动的情况下保持可见。
- 触屏设备必须可通过依次轻触两块切片完成与鼠标点击等价的选中、取消和交换操作；不得依赖悬停或右键。
- 关卡进入、切片交换、通关结果展示和下一关切换必须具有协调的基础过渡效果，不得因动画阻塞用户点击。

**验收标准**：在目标电脑浏览器中，用户无需离开游戏主界面即可同时看见拼图与计时器；关键状态变化存在可观察、无明显跳变的视觉反馈。

### FR-011：使用项目内置名画图库

**目标**：为完整 100 关提供稳定、随应用交付的图片资产。

**规则**：

- V1 使用已入库的 101 张互不重复名画资产及其 `manifest.csv`；图库允许在后续继续增加。每轮游戏固定为 100 关，而非按图库总数创建关卡。
- 运行时只读取项目内置图片与清单，不下载、替换或核验外部图片。
- 应用清单必须从现有字段提供唯一标识、作品名、作者/创作者、馆藏机构、图片本地路径、来源页、图片 URL 和许可证展示值；年代缺失时界面显示“年代未知”，实际宽高与方向从本地文件派生。
- 图库清单必须与图片资产一同版本管理；当项目负责人替换或新增图片时，相关元数据必须同步更新。

**验收标准**：图库清单中至少有 100 条唯一记录；两张固定练习图均存在且可加载；每条用于游戏的资产均有本地图片、作品名、作者、馆藏机构、来源页和许可证展示值，图片可被应用加载。

### FR-012：展示作品基本信息

**目标**：让用户知道正在拼合的是哪一幅作品，并保留必要的来源识别。

**规则**：

- 每关必须展示当前图片的作品名、作者/创作者、创作年代或年份和馆藏机构；信息由对应图片资产的元数据提供。
- 若创作年代或年份未知，界面必须显示“年代未知”，不得编造年份。
- 来源与许可信息必须可由用户在游戏内查看；具体展示形式可为信息面板、详情弹层或独立的图片来源页。
- 作品信息展示不得遮挡拼图操作区或计时器。

**验收标准**：进入任一具有完整测试元数据的关卡时，用户可看见该作品的基本信息，并能查看其来源和许可信息；未知年份按规定显示。

## 8. 非功能需求

### NFR-001：技术约束

- V1 必须使用 React + TypeScript 实现。
- 实现必须使用适当的数据结构管理切片当前位置与正确位置，使交换和完成判定可被自动化验证。

### NFR-002：可操作性与响应性

- V1 必须使用响应式布局：在宽度不小于 1024 CSS 像素的桌面视口采用左右布局；在宽度 360–1023 CSS 像素的窄视口采用单列布局。小于 360 CSS 像素时显示尺寸提示。
- V1 必须支持桌面版 Chrome、Edge、Firefox 的各自最新两个正式版本，以及桌面 Safari 的最新两个 macOS 支持版本；移动端支持 Android Chrome 与 iOS Safari 的各自最新两个正式版本。
- Internet Explorer 不属于 V1 支持范围。
- 切片选中与交换后的视觉状态必须清晰可辨。

### NFR-003：可靠性与数据边界

- 图片库、已用图片记录、关卡状态和计时状态必须在同一前端会话内保持一致。
- V1 不得要求用户输入、保存或传输个人信息、账号凭据或支付信息。
- V1 不得把图片或用户行为数据上传至未经项目负责人确认的外部服务。

### NFR-004：可测试性

- 难度计算、随机不重复选择、打乱、交换、完成判定和计时开始/停止语义必须可自动化验证。
- 浏览器中的桌面/触屏交互、响应式布局和动画连贯性必须通过 Level 2 人工验证。

## 9. 平台与外部限制

- 名画图片与初始清单已由项目负责人提供；图片本地可用性和应用清单映射是进入真实图片验收前的前置条件，不要求对现有许可证字段进行额外核验。
- 本期不依赖后端、数据库或第三方账户；如后续设计引入外部服务，必须重新评审范围与安全边界。

## 10. 迁移与兼容

这是新功能，不涉及旧功能迁移、数据迁移、影子运行或兼容回退。
