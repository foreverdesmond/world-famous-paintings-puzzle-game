# 世界名画拼图小游戏 V1：任务背景与现状分析

> 文档状态：已审核通过
> 版本：V1.2
> 调查范围：本地项目工作区、已确认的产品讨论记录与远端仓库元数据
> 数据快照时间：2026-08-30（Pacific/Auckland）
> 审核人：项目负责人
> 最后更新：2026-08-30

## 1. 背景与业务目标

项目负责人希望制作一款以世界名画为主题的轻量单人拼图小游戏。用户在浏览器中完成由一幅名画切分而成的拼图，以逐关提升的难度体验游戏，并在每关结束时看到自己的通关时间。

V1 的目标是以最小可用范围验证核心体验：用户能开始一轮游戏、完成切片交换、获得准确计时、连续挑战随机且不重复的名画，并自然地进入下一关或退出。

若不完成此迭代，项目只有一个空仓库，无法验证“名画主题 + 逐关拼图 + 计时反馈”的核心玩法是否成立，也无法为后续扩展图片库、移动端、排行榜或进度保存建立可靠基线。

## 2. 调查范围、方法与限制

### 已检查的事实

- 当前开发分支为 `DEV-001`，已同步包含远端 `main` 的图片资源提交；尚无应用代码、测试、配置或运行入口。
- `assets/paintings/` 已提供 101 张 JPEG 名画缩略图，长边约 1920px，总量约 94.3 MB；`manifest.csv` 有 101 条记录。
- 清单字段为 `title,artist,institution,licence,page_url,image_url,file,jpeg_bytes`；本次核验未发现创作年代、图片宽高或独立许可说明 URL 字段。
- 项目负责人已明确 V1 的玩法、技术栈和部分交互规则。

### 未检查的内容与原因

- 图片库的逐条权利字段仍需标准化核验：清单中 92 条为 `Public domain`、4 条为 `CC0`、1 条为 `CC0 (Met Open Access)`，另有 4 条仅写为 `Wikimedia Commons`，不符合“明确 CC0/公共领域”这一可机读口径。
- 尚无 React/TypeScript 工程，无法调查运行时拓扑、依赖、测试能力、构建流程或部署环境。
- 未连接任何生产环境、数据库、分析服务或第三方 API；本轮未执行外部写操作。

本文件的结论适用于“图片静态资产已入库、应用尚未开始实现”的当前阶段。

## 3. 当前系统架构与数据流

当前不存在可运行系统、数据流或外部服务。

已确认的目标运行路径如下，属于**需求方向**而不是现状事实：

```text
用户开始新游戏
  → 从本轮未使用的名画中随机选择一张
  → 根据关卡与图片横竖方向计算行列并切分
  → 打乱为未完成、可通过交换恢复的拼图
  → 用户首次点击切片后开始计时
  → 两次点击交换切片，直到全部位置正确
  → 展示本关耗时，选择下一关或退出
```

V1 计划使用 React + TypeScript 实现前端。具体组件、状态模型、资源加载方式、构建工具和部署方式尚未决定，不应在本阶段预设。

## 4. 当前数据模型与规模

当前没有数据模型或持久化数据。

已确认的目标数据规模与边界：

- 已入库图片为 101 张；每轮游戏固定为 100 关。图库可大于 100 张：第 1、2 关使用固定练习图，后 98 关从其余未使用图片中随机选择，因此单轮不要求用完图库。
- 每关消耗一张本轮尚未使用的图片；同一轮内不得重复。
- V1 不要求登录、服务端持久化、排行榜或跨会话进度保存。

图片文件格式、来源页和基础作品信息已随清单入库；图片实际宽高由应用从本地文件派生，年代缺失时运行时展示“年代未知”。现有许可证字段作为展示信息使用，不将逐项标准化或外部核验列为 V1 门禁。

## 5. 当前运行和更新机制

当前没有应用运行、发布、日志、告警、更新或恢复机制。V1 预期为浏览器内单人会话：退出游戏后不保存进度，下次开始新一轮游戏。

## 6. 运行时激活拓扑、生命周期与共享资源

当前无运行时入口、依赖注入、后台任务、并发模型或外部资源。

后续设计至少需要明确：

- 拼图状态、已用图片集合、当前关卡和计时状态的会话内所有权；
- 图片资源加载失败时的用户可见行为；
- 页面刷新、关闭或选择退出时会话状态的丢弃语义；
- 前端资源的缓存与释放边界。

## 7. 当前测试能力与证明边界

当前未创建测试工程、测试用例或可运行应用，因此没有自动化验证证据。

未来测试至少不能遗漏：拼图难度计算、随机选择不重复、打乱后未完成且可恢复、交换规则、完成判定与从首次点击开始的计时语义。视觉流畅性和实际鼠标操作需要在浏览器中人工验证。

## 8. 问题与风险清单

### P2：清单缺少部分运行时展示字段

- **现象**：清单没有创作年代和图片原始宽高字段。
- **证据**：`assets/paintings/manifest.csv` 的字段为 `title,artist,institution,licence,page_url,image_url,file,jpeg_bytes`。
- **根因/当前推断**：素材清单以下载与来源追溯为目的创建，未包含游戏展示和版式计算所需的派生字段。
- **影响**：应用需要定义缺失值与方向计算的确定行为，避免编造年代或按文件名猜测方向。
- **触发条件**：资源接入和作品信息展示。
- **本期处理**：方向从实际图片尺寸读取；无年代显示“年代未知”；不新增逐项许可证核验任务。

### P2：资源容量随未来扩图增长

- **现象**：图库现有 101 张，后续还会继续增加；游戏一轮固定为 100 关。
- **影响**：资源选择必须从可用图库中抽取而非假设图库恰为 100 张，同时仍须确保单轮无重复。
- **本期处理**：固定练习图先占用两张，后 98 关从剩余可用池无放回随机选择；图库必须至少有 100 张合格资产，增加资产不改变关卡数或难度规则。

### P2：高难度图片尺寸与可操作性风险

- **现象**：100 张图片的规则会产生 20 个正式难度，最后 Level 20 为 12×12、共 144 块。
- **证据**：已确认的 2 个练习关 + 每个正式难度 5 关 + 100 张图片的关卡规则。
- **影响**：低分辨率图片、较小窗口或小屏幕可能导致切片过小，影响鼠标操作和视觉辨识。
- **触发条件**：在高难度或较小浏览器视口中运行。
- **根因/当前推断**：12×12 棋盘在窄视口中可用空间有限，固定双栏布局会压缩切片与计时信息。
- **本期处理**：V1 使用响应式布局；桌面保留左右布局，窄视口改为拼图区优先的单列布局，并在 Level 2 对目标桌面和移动浏览器验证。

### P2：图片加载最终失败将中断当前游戏流程

- **现象**：图片加载可重试 5 次，但连续失败后必须向用户提示“游戏故障”。
- **证据**：项目负责人已确认加载失败时重试 5 次，仍失败则提示游戏故障。
- **影响**：用户不能完成当前关；V1 不采用静默替换为另一张图片的方式掩盖资源故障。
- **触发条件**：同一关卡图片连续 5 次加载失败。
- **本期处理**：在需求和验收中明确重试次数、终止条件与提示行为。

## 9. 可保留的既有能力

- 已初始化的 Git 仓库、`main`、`DEV-001` 分支及远端关联可继续作为版本管理基线。
- 已入库的 101 张本地静态名画与 `manifest.csv` 可作为图片接入和资源验收基线。
- 现有 `.gitignore` 已覆盖 .NET、常见前端构建产物、日志、密钥以及 macOS/Windows 系统文件，可继续保留。

## 10. 约束与不变量

- V1 必须使用 React + TypeScript，并以响应式布局支持桌面和移动浏览器。
- V1 的核心操作是鼠标两次单击交换两个切片，不以拖拽作为必需交互。
- 每张图片在同一轮游戏中只能出现一次；退出后不保留进度，重新开始进入新一轮。
- V1 使用项目已入库的图片与清单；运行时不得下载、上传或替换图片。
- 每个图片资产必须展示作品基本信息；现有清单缺失的年代显示“年代未知”，宽高从文件读取。
- 计时从用户首次点击切片开始，而不是图片显示或关卡加载时开始。
- 每关开始时必须先展示完整原图 5 秒，作为拼图提示；提示结束后才允许拼图交互。
- 初始布局必须未完成，且必须能只通过两两交换切片恢复到正确布局。
- 横版及正方形图片优先增加列；竖版图片优先增加行。
- 本期不应未经授权接入付费服务、上传图片或调用外部数据服务。

## 11. 候选方向（尚未确认）
