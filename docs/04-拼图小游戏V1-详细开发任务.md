## 1. 范围与路线选择

本迭代交付一个可在桌面与移动浏览器运行的响应式 React + TypeScript 拼图游戏。101 张本地图片与初始清单已经入库；资源接入只负责清单映射、图片尺寸派生和本地可用性校验，不执行许可证字段标准化或外部核验。

每个编码任务应从 `DEV-001` 创建独立任务分支并在独立工作目录完成，经过独立审查后再精确合入 `DEV-001`。项目负责人批准后，`DEV-001` 才可进入 `main`。

## 2. 不可变基线、任务状态与派发契约

本文件在审核通过并提交后，其提交 SHA 是 `TaskDocumentBaselineRef`；需求、设计和任务文档均必须以该提交中的精确版本为准。每次派发编码任务时，协调者必须记录当时的 `CodeBaseSHA`、任务分支、独立工作目录、需求/设计/任务文档基线提交、预期审核提交范围和合并目标。不得以可变工作目录路径代替这些基线。

每项任务遵循以下状态链：`Planned → Ready → InProgress → Submitted → InReview → TaskAccepted → MergePending → Integrated → IntegrationVerified`；出现明确的授权、范围或环境阻塞时标记 `Blocked`。项目负责人维护当前状态；本项目尚未启用 Hermes 台账，因此不进行自动派发或自动状态消费。

所有 `CodingTask` 继承此契约：

| 字段 | 派发时要求 |
| --- | --- |
| `TaskBranch` | 使用任务章节定义的唯一分支名，从 `DEV-001` 创建。 |
| `WorktreePath` | 创建任务专属工作目录后记录；不得与其他编码任务共享。 |
| `CodeBaseSHA` | 从 `DEV-001` 创建任务分支前记录。 |
| `ReviewedCommitRange` | 记录 `CodeBaseSHA..HeadSHA`；新提交会使旧审查结论失效。 |
| `MergeTarget` | 仅独立合并任务可将通过审查的精确 `HeadSHA` 合入 `DEV-001`。 |
| `NotRun` | 必须说明未运行原因、风险、后续责任人与阻塞阶段。 |

## 4. 详细任务

### DEV-001-T001：初始化 React + TypeScript 工程

> Route：Standard
> Risk：Low
> TaskType：CodingTask
> TaskBranch：`task/DEV-001-T001`
> MergeTarget：`DEV-001`
> 依赖：无

**目标与范围**：创建可在本地运行、构建和测试的 React + TypeScript 前端工程，并建立基础目录、样式入口和测试入口。

**允许修改**：工程配置、应用入口、基础样式、测试配置和相关说明文件。

**禁止事项**：不得接入账号、后端、第三方分析、在线图片下载或真实外部写操作。

**Level 0 证据**：依赖安装、类型检查、生产构建和空壳测试通过。

### DEV-001-T002：实现纯拼图规则与单元测试

> Route：Standard
> Risk：Medium
> TaskType：CodingTask
> TaskBranch：`task/DEV-001-T002`
> MergeTarget：`DEV-001`
> 依赖：T001 已集成

**目标与范围**：实现关卡到行列的计算、方向判断、无重复图片选择、非完成打乱、两次点击交换、完成判定和耗时格式化。

**必须覆盖的边界**：第 1–2 固定练习图、3、7、8、12、13、98、100 关；横版、竖版、正方形；重复点击取消；初始布局不完成；图库大于 100 时一轮 100 图无重复。

**禁止事项**：规则模块不得依赖 React、DOM 或资源 URL。

**Level 0 证据**：规则单元测试与类型检查通过。

### DEV-001-T003：建立图片清单契约与真实资源接入

> Route：Standard
> Risk：Low
> TaskType：CodingTask
> TaskBranch：`task/DEV-001-T003`
> MergeTarget：`DEV-001`
> 依赖：T001 已集成

**目标与范围**：实现 `Artwork` 清单读取和运行时校验；将 `assets/paintings/manifest.csv` 映射为应用清单，读取本地图片宽高并覆盖横、竖、正方形方向及作品信息展示。

**边界**：不得下载、上传、删除或替换现有图片；许可证字段按 `manifest.csv` 原值映射和展示，不执行外部核验。

**Level 0 证据**：清单唯一性、固定练习图存在、图片路径、派生尺寸/方向与缺失年代回退测试通过。

### DEV-001-T004：实现游戏会话、计时和图片加载状态

> Route：Standard
> Risk：Medium
> TaskType：CodingTask
> TaskBranch：`task/DEV-001-T004`
> MergeTarget：`DEV-001`
> 依赖：T002、T003 已集成

**目标与范围**：实现开始、原图提示 5 秒、首次点击计时、关卡切换、退出、图片预加载和最多 5 次重试。

**关键语义**：预览期不能操作或计时；失败后仅显示故障和退出；刷新不恢复；第 100 关进入最终完成状态。

**Level 0 证据**：受控时钟和图片加载替身下的状态转换测试通过。

### DEV-001-T005：实现拼图棋盘、信息面板与电脑端布局

> Route：Standard
> Risk：Medium
> TaskType：CodingTask
> TaskBranch：`task/DEV-001-T005`
> MergeTarget：`DEV-001`
> 依赖：T004 已集成

**目标与范围**：实现 CSS Grid 拼图、切片选中与交换交互，以及关卡、计时和作品信息面板；计时状态组须同时显示“第 X / 100 关”、练习关/正式 Level 标识和实时耗时。宽度不小于 1024px 时采用左右布局，360–1023px 时采用拼图区优先的单列布局，小于 360px 显示尺寸提示。

**关键语义**：切片背景按正确位置显示；点击已选切片取消选择；来源与许可信息可查看；不能遮挡操作区。

**Level 0 证据**：组件测试覆盖选择、取消与交换。
**Level 1 证据**：组件/本地浏览器检查 2×2、3×4 与 12×12 的基础视觉可用性。

### DEV-001-T006：实现通关、故障和动画反馈

> Route：Standard
> Risk：Low
> TaskType：CodingTask
> TaskBranch：`task/DEV-001-T006`
> MergeTarget：`DEV-001`
> 依赖：T004、T005 已集成

**目标与范围**：实现第 1–99 关的通关结果和下一关/退出操作；第 100 关的基础通关动画和退出操作；故障状态的退出操作；实现不阻塞点击的基础过渡并支持减少动画偏好。

**Level 0 证据**：组件/状态测试覆盖普通通关、最终通关与故障退出。
**Level 1 证据**：浏览器人工验证动画平滑且操作不被阻塞。

### DEV-001-T007：核心玩法集成验证

> Route：Standard
> Risk：Medium
> TaskType：IntegrationValidationTask
> TaskBranch：`validation/DEV-001-T007`
> MergeTarget：`DEV-001`
> 依赖：T001–T006 已集成

**目标与范围**：使用生产构建与已入库本地图片，验证从开始、预览、操作、通关、下一关、故障和退出的完整核心路径。

**安全边界**：仅使用已入库本地资源；不得下载、上传或变更图库。

**验证责任**：Level 1 本地流程验证；目标桌面与移动浏览器的响应式兼容性由 T008 在 Level 2 验证。若目标浏览器环境不可用，记录 `NotRun`、原因和项目负责人后续验证责任。

### DEV-001-M001：独立审查与迭代精确合并

> Route：Standard
> Risk：Medium
> TaskType：IterationMergeTask
> TaskBranch：`merge/DEV-001-M001`
> MergeTarget：`DEV-001`
> 依赖：每个待合并任务均已 `TaskAccepted`

**目标与范围**：对 T001–T006 的每个精确候选提交执行独立代码审查；只有没有未关闭问题的候选才可合入 `DEV-001`。合并执行者不得修改候选内容来使其通过。

**审查重点**：需求与设计一致性、任务范围、SOLID、测试证据、`CodeBaseSHA..HeadSHA` 绑定，以及没有引入未经授权的外部访问或变更已入库图库。

**完成证据**：每个候选的审核范围、结论、发现项、`HeadSHA` 与实际合入提交；被拒绝候选返回其原任务分支返工。

### DEV-001-M002：主分支合并

> Route：Standard
> Risk：Medium
> TaskType：MainMergeTask
> TaskBranch：`merge/DEV-001-M002`
> MergeTarget：`main`
> 依赖：T007、T008 均已 `IntegrationVerified`，项目负责人明确批准

**目标与范围**：将已通过集成验证的 `DEV-001` 精确合入 `main`。不得替代项目负责人的最终业务批准。

**完成证据**：批准记录、被合并的精确 SHA、合并后分支状态，以及适用的 Level 1–2 验证结论。

### DEV-001-T008：Level 2 响应式与多浏览器验证

> Route：Standard
> Risk：Medium
> TaskType：IntegrationValidationTask
> TaskBranch：`validation/DEV-001-T008`
> MergeTarget：`DEV-001`
> 依赖：T007 已通过

**目标与范围**：以生产构建和已入库图片验证桌面 Chrome、Edge、Firefox、Safari，以及 Android Chrome、iOS Safari 最近两个正式版本中的响应式布局、鼠标/触屏交换、计时与完整流程；同时验证第 1–2 关固定使用指定练习图，后 98 关随机且无重复。

**完成证据**：本地资源映射校验、100 关无重复选择测试、1024×768 与 360×640 视口的目标浏览器验证记录、鼠标/触屏操作截图或录屏，以及 `NotRun` 项说明。该任务完成前，不得宣称 V1 已完成目标浏览器兼容性验证。

## 5. SOLID 审查重点

- T002 必须保持规则模块独立于 React 和资源加载。
- T003 只负责资源契约，不承担游戏流程。
- T004 只编排会话状态，不在其中复制难度或交换算法。
- T005/T006 只呈现状态和发出意图，不直接修改棋盘数据。

## 6. Level 1–3 交接与 NotRun

- Level 0：每个编码任务在其任务分支中完成定向测试。
- Level 1：T007 在 `DEV-001` 集成后执行本地浏览器交互与布局验证。
- Level 2：T008 使用生产构建和已入库本地资源验证目标桌面与移动浏览器、响应式布局及核心路径。
- Level 3：N/A；V1 不要求外部许可证或授权审计。
- 未能运行任一目标浏览器时，必须记录 `NotRun`、环境限制、风险及项目负责人后续验证责任。
